# Halftone (Vite + Workers) — design system

The rules this app is built with. The full system, with every component and pattern, is the web kit's:
halftonedesignsystem.com (and halftonedesignsystem.com/llms.txt for agents). The tokens, and how they read, are in
`DESIGN.md` (generated by `npm run tokens:build`).

## Colour

Semantic classes only: `bg-background`, `bg-card`, `text-foreground`, `text-muted-foreground`, `border-border`,
`bg-primary` with `text-primary-foreground`, `bg-primary-subtle`, and the tones (`success`, `warning`,
`destructive`, `info`) the same way. Never hex, never Tailwind's palette (`text-red-500`), never a colour at an
opacity (`bg-primary/10`). *Why:* the classes come from the tokens, so a re-brand or dark mode changes every page
at once, and every pairing is checked for WCAG AA contrast when the tokens build.

On a tint, keep the text `text-foreground` and let the tint, an icon or a dot carry the colour (the status badges
in `src/pages/projects.tsx` do this). A tone's text on its own tint often falls below 4.5:1.

## Component registry

Pages build only from these. Their API is in each file's doc comment and in llms.txt.

| Component | From | Use it for |
| --- | --- | --- |
| `AppShell` | `@/components/kit/app-shell` | the frame: sidebar nav, mobile sheet, top bar |
| `PageHeader` | `@/components/kit/page-header` | a page's title, description and one primary action |
| `StatTile` | `@/components/kit/stat-tile` | one KPI with a signed change; 2–4 in a row |
| `DataTable` | `@/components/kit/data-table` | a sortable table with a built-in empty state |
| `ListGroup`, `ListRow` | `@/components/kit/list-group`, `list-row` | settings and lists of rows |
| `SegmentedControl` | `@/components/kit/segmented-control` | 2–4 exclusive options (give it a width) |
| `EmptyState` | `@/components/kit/empty-state` | nothing here yet, and the way forward |
| `Spinner` | `@/components/kit/spinner` | loading |
| `Button` | `@/components/ui/button` | actions; links as `<Button asChild><Link to=… /></Button>` |
| `Badge` | `@/components/ui/badge` | a status or a count |
| `Card` | `@/components/ui/card` | a surface for a chart or a group |
| `ChartContainer` | `@/components/ui/chart` | every chart (series colours from `var(--chart-N)`) |
| `Alert` | `@/components/ui/alert` | an error or a notice in the page |
| `Switch` | `@/components/ui/switch` | an on/off setting |
| `Sheet`, `Table` | `@/components/ui/sheet`, `table` | used by AppShell and DataTable |

Need another: `npx shadcn@latest add @halftone-web/<name>`. It lands in `src/components/kit` or `ui`, and the lint
rule allows it from then on.

## Patterns

- **A page:** `PageHeader`, then the content in a `flex flex-col gap-8` column. One primary action per page.
- **Loading and errors:** `LoadState` (`src/components/load-state.tsx`) while `useApi` loads, and when it fails,
  with a way to try again. An empty list says so with `EmptyState` and offers the next step.
- **Dashboards:** `StatTile`s in `grid gap-4 sm:grid-cols-2 xl:grid-cols-4`, then a chart in a `Card`, then a table.
- Content is flat; shadows only on what you can press or what floats.

## Hallucination guard

If a component isn't in the table above or in llms.txt, it doesn't exist. Say so in one line and add the closest
kit component; don't invent one, and don't build a look-alike from `div`s.
